# Project-local Codex Model Routing

이 문서는 이 저장소의 Codex 작업 배정 규칙이다. 전역 `~/.codex` 설정은 변경하지 않는다. `Goal.md`와 worksheet가 존재할 경우 사용자와 Sol만 수정하며, 여러 Sol 세션이 같은 worksheet를 동시에 관리하지 않는다. 둘 중 필요한 문서가 없으면 임의 생성하거나 상태를 추정하지 않고 Sol에 `NEEDS_DECISION`으로 반환한다.

## 모델 x 추론 단계 라우팅 매트릭스

| 모델 | Light (`low`) | 중간 (`medium`) | 높음 (`high`) | 매우 높음 (`xhigh`) |
| --- | --- | --- | --- | --- |
| 5.6 Sol | 빠른 최종 판정. 대부분 과투자 | 기본 지휘자: 분해, 배정, 통합 | 아키텍처, 난해한 문제, 중요 리뷰 | 고위험 결정, 상충 결과 판정, 최종 감사 |
| 5.6 Terra | 코드 탐색, 제한된 수정 | 기본 작업자: 구현, 조사, 도구 사용 | 복합 구현, 다중 파일 디버깅, 독립 리뷰 | 보통 Sol High로 올리는 편이 효율적 |
| 5.6 Luna | 추출, 분류, 스캔, 포맷 변환 | 반복 변환, 구조화, 정형 요약 | 예외가 있는 명확한 배치 작업 | 사용하지 않고 Terra 또는 Sol로 승격 |
| 5.5 | 결과 비교 | 기존 5.5 워크플로 유지 | 회귀 비교 | 신규 기본 경로에는 비추천 |
| 5.4 | 작은 기존 작업 | 5.4 고정 프로젝트 | 호환성, 재현 목적 | 신규 작업에는 비추천 |
| 5.4 Mini | grep, 파일 맵, 목록화 | 기계적 수정, 테스트 생성, 문서 정리 | 제한된 작업만 | 실패하면 Terra로 승격 |
| 5.3 Codex Spark | 즉석 질의, 코드 탐색 | 실시간 국소 수정, 빠른 반복 | 복잡해지면 Terra로 전환 | 부적합 |

앱의 Light, 중간, 높음, 매우 높음은 각각 config의 `low`, `medium`, `high`, `xhigh`에 대응한다.

## Max와 Ultra

- Max는 하나의 난해한 작업을 단일 모델이 더 깊게 판단해야 할 때만 사용한다.
- Ultra는 의미 있게 분리 가능한 복합 작업에서 자동 하위 에이전트 위임이 필요할 때만 사용한다.
- 대부분의 일반 작업에는 Max와 Ultra를 사용하지 않는다.

## 강제 라우팅 규칙

1. 작업이 모호하면 먼저 Sol Medium 또는 High가 명세화한다.
2. 명세와 완료조건이 확정되면 Terra 또는 Luna로 하향 배정한다.
3. 일반 구현의 기본값은 Terra Medium이다.
4. 다중 파일 수정, 복잡한 디버깅, 독립 리뷰는 Terra High다.
5. 추출, 분류, 변환, 목록화처럼 명확한 작업은 Luna Light다.
6. 여러 단계가 있지만 결과 형식이 명확한 반복 작업은 Luna Medium이다.
7. Luna High는 예외 처리가 있지만 범위와 완료조건이 명확할 때만 사용한다.
8. Luna xhigh는 사용하지 않는다.
9. Luna가 요구사항 해석이나 파일 관계를 반복해서 놓치면 Terra Medium으로 승격한다.
10. Terra Medium이 설계 판단에서 실패하면 Terra xhigh가 아니라 Sol High로 승격한다.
11. Sol Medium은 상시 지휘와 통합의 기본값이다.
12. Sol High는 설계, 난해한 문제, 중요 리뷰에 사용한다.
13. Sol xhigh는 고위험 결정, 상충된 검토 결과, 최종 감사에만 사용한다.
14. Sol을 단순 구현, 대량 추출, 원시 로그 분석에 사용하지 않는다.
15. 5.4 Mini Light는 파일 검색, 목록화, 코드 위치 확인에 사용한다.
16. 5.4 Mini Medium은 기계적 수정, 테스트 후보 생성, 문서 정리에 사용한다.
17. 5.4 Mini가 범위 밖 판단을 요구받으면 Terra로 승격한다.
18. Spark Light는 즉석 코드 질의와 탐색에 사용한다.
19. Spark Medium은 사용자가 직접 지켜보는 짧은 수정 반복에 사용한다.
20. Spark 작업이 여러 파일, 설계, 장시간 검증으로 확대되면 Terra로 전환한다.
21. 5.5와 5.4는 신규 작업의 기본 모델로 사용하지 않는다.
22. 5.5와 5.4는 기존 워크플로 재현, 회귀 비교, 호환성 확인에만 사용한다.
23. 약한 모델에 xhigh를 주어 문제를 계속 해결하게 하지 않는다.
24. 완료조건을 내는 가장 낮은 모델과 추론 단계를 우선 사용한다.

## 승격과 하향

- 모호한 요청은 Sol Medium에서 명세하고, 아키텍처 또는 위험 판단이 크면 Sol High로 시작한다.
- 완료조건이 고정되면 구현은 Terra Medium, 정형 배치는 Luna Light 또는 Medium으로 내린다.
- 첫 단순 테스트 실패는 같은 작업자가 한 번 재시도한다.
- 같은 유형으로 두 번 실패하면 추론 단계를 한 단계 올린다.
- 요구사항 해석 실패는 상위 모델로 전환한다.
- 설계 또는 범위 판단 문제는 즉시 Sol High로 반환한다.
- 세 번째 실패는 `BLOCKED`다. 범위 밖 파일 수정이 필요하면 `NEEDS_DECISION`이다.
- 구현자와 검증자는 분리하며 무한 재시도하지 않는다.

## 하위 에이전트와 별도 세션

하위 에이전트는 같은 최종 결과를 위한 짧은 독립 탐색, 조사, 테스트, 읽기 작업, 원시 로그 요약에 사용한다. Sol이 모든 결과를 수집해 최종 판단한다. 하위 에이전트의 재귀 생성은 금지한다.

별도 세션은 독립 산출물, 장시간 구현, 사용자별 트랙 조정, 별도 branch와 diff 검토, 서로 다른 목표나 권한이 필요한 작업에 사용한다. 파일을 수정하는 별도 세션은 Git Worktree를 사용하고 같은 checkout을 동시에 수정하지 않는다.

## 작업 위험도별 검토 모델

| 위험도 | 구현 또는 조사 | 검토와 판정 |
| --- | --- | --- |
| 낮음: 읽기, 목록, 정형 변환 | Luna Light 또는 Mini Light | Sol Light 또는 Terra Medium |
| 보통: 단일 영역 구현 | Terra Medium | Terra High |
| 높음: 다중 파일, 운영 영향, 복잡한 장애 | Terra High | Sol High |
| 매우 높음: 보안, 되돌리기 어려운 결정, 상충 결과 | Terra High의 독립 근거 | Sol xhigh 최종 감사 |

## 모델 선택 예시

- 저장소 파일 맵 작성: Mini Light.
- CSV 또는 로그를 정해진 표로 변환: Luna Light.
- 반복 문서 묶음을 동일 형식으로 요약: Luna Medium.
- 명세가 확정된 일반 기능 구현: Terra Medium.
- 여러 모듈을 가로지르는 장애 수정: Terra High, 이후 별도 Terra High 리뷰.
- 불명확한 운영 아키텍처 결정: Sol High가 명세와 선택을 담당하고 구현은 Terra로 하향한다.
- 고위험 배포 전 상충 리뷰 판정: Sol xhigh.
- 사용자가 직접 보는 짧은 실시간 코드 반복: Spark Light 또는 Medium. 장기화하면 Terra로 전환한다.

## 사용 금지 조합

- Luna xhigh.
- Mini xhigh 또는 Spark High/xhigh.
- Terra Medium 설계 실패를 Terra xhigh로 반복하는 방식.
- Sol을 대량 추출, 단순 구현, 원시 로그 처리에 고정하는 방식.
- 5.5와 5.4를 신규 작업의 기본값으로 사용하는 방식.
- 범위와 완료조건이 모호한 상태에서 Luna 또는 Mini에 writer 권한을 주는 방식.
- 같은 파일에 여러 writer를 배정하거나 하위 에이전트가 재귀적으로 에이전트를 생성하는 방식.

## 작업 소유권과 반환 형식

- `Goal.md`: 사용자와 Sol만 수정한다.
- worksheet: Sol만 상태를 수정한다.
- 작업 패킷: Sol이 작성한다.
- 구현 파일: 배정된 작업자 한 명만 수정한다.
- 리뷰 결과: 구현자와 분리된 reviewer가 작성한다.
- 통합, merge, 최종 `DONE` 판정: Sol만 수행한다.

모든 작업자는 다음 형식으로 반환한다.

1. `STATUS: DONE | BLOCKED | NEEDS_DECISION`
2. `TASK-ID`
3. 수행한 작업
4. 변경 파일
5. 실행한 검증과 결과
6. 완료조건별 `PASS/FAIL`
7. 남은 위험과 가정
8. 사용한 모델과 추론 단계
9. Sol이 다음에 수행할 정확한 행동

## 현재 모델 ID 적용 경계

- 현재 로컬 Codex 모델 카탈로그에서 `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna`, `gpt-5.5`, `gpt-5.4`, `gpt-5.4-mini`, `gpt-5.3-codex-spark`를 확인했다.
- 모든 모델은 `low`, `medium`, `high`, `xhigh`를 지원한다. Sol과 Terra는 `max`, `ultra`도 지원하고 Luna는 `max`도 지원한다.
- Spark는 현재 세션의 자율 하위 에이전트 override 목록에 없고 실시간 사용자 주도 작업에 배정하므로 custom agent로 만들지 않는다.
- 5.5와 5.4는 회귀 또는 호환성 요구가 생기기 전까지 custom agent로 만들지 않는다.
- 확인되지 않은 모델 ID는 config 또는 custom agent에 추가하지 않는다.
